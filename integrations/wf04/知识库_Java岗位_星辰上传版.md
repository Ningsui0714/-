## 类的定义与对象创建（KN_JAVA_CLASS）

### Java 类与对象的基本概念【概念】

类是 Java 程序的基本组织单位，用 class 关键字定义；对象是类的实例，用 new 关键字调用构造器创建。类由字段（成员变量）、方法、构造器组成。例如 Student 类封装了学生信息，通过 new Student() 创建具体学生对象。理解类与对象的关系是学习面向对象的第一关。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 1 节：类的定义与对象创建

### 定义类并创建对象【步骤】

1) 用 class 关键字定义类并命名（大驼峰）；2) 声明字段与方法；3) 定义构造器（与类同名、无返回值）；4) 在方法中用 new 类名() 创建对象；5) 通过引用变量访问对象成员。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 2 节：类的定义与对象创建

### 类与对象的常见误区【易错点】

误区：把类当对象直接使用（Student.name 而非实例访问）；忘记定义构造器或写错构造器名称；使用未初始化的引用导致空指针。命名要求：类名大驼峰、方法小驼峰、常量全大写。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 3 节：类的定义与对象创建

### 成绩管理中的学生类设计【案例】

成绩管理系统中，学生信息用 Student 类建模：字段包括姓名 name、成绩数组 scores、缺考标记 isAbsent；方法提供录入成绩、查询成绩、判断是否缺考等能力。用 new Student() 创建每个学生对象，对象各自持有自己的数据，互不干扰——这正是用类建模的现实意义。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 1 节：类的定义与对象创建（成绩管理示例）

### 真实开发中类的职责划分【岗位应用】

岗位实践中，一个类通常只负责一类职责（单一职责）：Student 管学生数据、ScoreCalculator 管统计、ReportPrinter 管输出。开发成绩管理模块时先画类图再写代码，避免把统计逻辑全塞进一个类导致难维护。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 1 节：类的定义与对象创建（岗位用法）

### 命名规范与 1+X 考核要求【规范】

Java 命名规范是职业开发的基本要求：类名大驼峰（StudentScore）、方法名小驼峰（getAverage）、常量全大写加下划线（MAX_SCORE）、包名全小写。1+X Java 应用开发等级证书考核包含代码规范与可读性要求，命名违规会直接扣分。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 1 节：类的定义与对象创建（规范）

### 成绩数据脱敏与隐私保护【安全】

学生成绩属于个人信息，按 GB/T 35273-2020《个人信息安全规范》应最小化收集与展示：客户端不显示完整学号、列表页默认隐藏不及格名单的姓名、导出文件加密。开发时在数据访问层统一脱敏，避免前端直接拿到全量原始数据。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 1 节：类的定义与对象创建（数据安全）

### 构造器与重载【概念】

构造器与类同名、无返回值，用 new 调用。可以重载：如 Student() 无参构造、Student(String name) 带名构造。若定义任何构造器，编译器不再自动生成默认无参构造，需按需显式声明。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 1 节：类的定义与对象创建

## 封装与访问控制（KN_JAVA_ENCAPSULATION）

### 封装的本质：私有字段 + 公有方法【概念】

封装要求将内部数据声明为 private，通过 public 的 getter/setter 方法提供受控访问。例如成绩数组 scores 应保持 private，外部通过 getScores() 获取副本、setScores() 校验后写入，避免外部直接修改内部状态导致数据不一致。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 4 节：封装与访问控制

### 实现封装的标准步骤【步骤】

1) 字段全部设为 private；2) 为需要暴露的字段编写 getter（返回副本或不可变视图）；3) 为允许修改的字段编写 setter 并在其中做合法性校验（如 null/越界检查）；4) 内部统计逻辑收敛到类内方法，不暴露数组引用。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 5 节：封装与访问控制

### 封装常见错误【易错点】

错误一：getter 直接返回内部数组引用，调用方可绕过校验修改数据；错误二：把字段设为 public 图省事；错误三：setter 不做 null 校验导致统计口径混入无效数据。封装被绕过是设计层面的高频扣分点。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 6 节：封装与访问控制

### 成绩统计中的 getter 访问【案例】

成绩统计场景：scores 字段保持 private，外部统计代码通过 getValidScores() 获取已过滤缺考的有效成绩集合，而不是直接访问数组。这样统计口径统一（分子分母来自同一集合），且后续修改过滤规则只改类内一处。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 4 节：封装与访问控制（成绩管理示例）

### 生产代码为什么强制封装【岗位应用】

真实项目中封装防止三类事故：字段被外部随意改坏、校验逻辑被绕过、重构内部表示时牵连全部调用方。团队规范通常要求所有字段 private、对外只暴露必要方法，CR 时发现 public 字段直接打回。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 4 节：封装与访问控制（岗位用法）

### 访问控制与最小暴露原则【规范】

Java 访问修饰符：private（仅类内）、包私有（默认）、protected（子类+同包）、public（全局）。规范要求：字段一律 private；方法能 private 不 public；对外接口只暴露必要成员，遵循最小暴露原则，减少类的外部耦合面。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 4 节：封装与访问控制（规范）

### getter 返回副本防止外部篡改【安全】

getter 直接返回内部数组引用，外部就能绕过 setter 校验修改数据（如把缺考标记清掉）。安全做法：getValidScores() 返回过滤后数组的副本（clone）或不可变列表，保证内部状态只能被类内方法修改。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 4 节：封装与访问控制（数据安全）

### getter 返回副本还是引用【概念】

基本类型 getter 直接返回值即可；引用类型（数组、List）getter 应返回防御性副本或 Collections.unmodifiableList，否则调用方拿到的仍是内部引用。返回副本有性能成本，需要与封装收益权衡，但成绩数组这类可变数据必须防御。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 4 节：封装与访问控制

## 继承与方法重写（KN_JAVA_INHERITANCE）

### 继承与重写【概念】

子类通过 extends 继承父类，复用父类字段与方法；子类可以重写（override）父类方法改变行为，用 @Override 注解标记。重写方法签名必须与父类一致，super.方法名() 可调用父类被覆盖的版本以复用原有逻辑。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 7 节：继承与方法重写

### 正确使用继承与 super【步骤】

1) 用 extends 声明继承关系；2) 需要差异化行为时重写父类方法并加 @Override；3) 在重写方法中用 super.方法() 复用父类统计逻辑；4) 在子类中叠加差异化处理（如加分逻辑）；5) 构造器第一行调用 super() 初始化父类。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 8 节：继承与方法重写

### 继承易错点【易错点】

重写方法访问权限不能比父类更严格；构造器必须调用父类构造器；super 与 this 的区分（super 调父类、this 调本类）；误把重载当重写（参数列表不同是重载不是重写）。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 9 节：继承与方法重写

### 子类扩展成绩统计【案例】

成绩管理扩展场景：StudentWithBonus 继承 Student，重写 averageScore() 加入平时分加权，用 @Override 注解；super.averageScore() 先拿父类有效成绩的平均，再叠加加分。继承让新需求复用已有逻辑，只改差异部分。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 7 节：继承与方法重写（成绩管理示例）

### 继承在开发框架中的使用【岗位应用】

真实开发中继承用得克制：框架扩展（继承基类重写钩子方法）、模板方法模式、复用一组强相关类。判断标准是 is-a 关系是否成立——BonusStudent 是 Student 才用继承；只是复用代码应优先用组合。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 7 节：继承与方法重写（岗位用法）

### 组合优先于继承原则【规范】

Effective Java 与团队规范普遍推荐组合优先于继承：继承破坏封装（子类依赖父类实现细节）、父类变更易牵连子类。能用组合（持有引用、委托调用）就不用继承；必须继承时深度不超过两层。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 7 节：继承与方法重写（规范）

### 重写不得降低访问权限【安全】

重写父类方法时不能降低访问权限（父类 public 子类不能改 private），否则编译报错；也不能抛出更宽泛的异常。这是编译器的安全约束，防止通过子类绕过父类的访问控制承诺。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 7 节：继承与方法重写（安全约束）

### 方法重载与方法重写【概念】

重载（overload）：同类内同名不同参数列表，编译期决定调用哪个；重写（override）：子类覆盖父类方法，方法签名一致，运行期动态绑定。重载是静态多态，重写是动态多态，两者别混淆。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 7 节：继承与方法重写

## 多态与接口（KN_JAVA_POLYMORPHISM）

### 多态：父类引用指向子类对象【概念】

多态指父类引用变量可以指向子类对象，调用被重写方法时运行期动态绑定到实际类型。接口（interface）定义行为契约，类通过 implements 实现接口。多态让代码面向抽象编程，降低模块耦合。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 10 节：多态与接口

### 运用多态解耦【步骤】

1) 提取公共行为到父类方法或接口；2) 子类/实现类重写具体逻辑；3) 用父类或接口类型声明变量、接收子类对象；4) 调用方法时由运行期决定执行哪个版本；5) 需要时用 instanceof 安全判断实际类型。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 11 节：多态与接口

### 多态陷阱【易错点】

陷阱一：子类特有方法无法通过父类引用直接调用；陷阱二：字段访问不参与多态（字段按声明类型解析）；陷阱三：过度使用 instanceof 破坏多态，应优先利用重写机制。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 12 节：多态与接口

### 用接口抽象成绩统计【案例】

成绩系统把统计器抽象成接口 AverageCalculator，Averager 和 WeightedAverager 两个实现各自计算平均分。调用方只依赖接口，换实现（如改为排除缺考后再平均）不用改调用代码——多态让系统可扩展。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 10 节：多态与接口（成绩管理示例）

### 接口解耦与依赖注入【岗位应用】

岗位实践中接口用于解耦层与层：Service 依赖 Repository 接口而非具体类，测试时注入 Mock 实现。Spring 的依赖注入、MyBatis 的 Mapper 接口都是这一思想。判断标准：调用方只该知道能做什么，不该知道怎么实现。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 10 节：多态与接口（岗位用法）

### 接口设计规范：最小且稳定【规范】

接口设计遵循：方法数量尽量少、语义稳定、只暴露调用方需要的能力；接口变更会影响所有实现与调用方，发布后改接口视为破坏性变更。团队规范通常要求接口带清晰 Javadoc。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 10 节：多态与接口（规范）

### 接口暴露最小化与默认方法【安全】

接口是系统的公共契约，暴露越多实现方负担越重、攻击面越大。Java 8+ 用 default 方法给接口加默认行为，避免破坏已有实现；数据访问接口不应暴露底层字段或裸 SQL，统一走受控方法。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 10 节：多态与接口（安全约束）

### 抽象类与接口的区别【概念】

抽象类可有字段、构造器和部分实现，适合 is-a 强绑定（StudentBase 抽公共字段）；接口只能定义契约（Java 8+ 可有 default/static 方法），适合 can-do 能力抽象。一个类只能继承一个父类、可实现多个接口——多实现需求下优先接口。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 10 节：多态与接口

## 集合与泛型（KN_JAVA_COLLECTION）

### 常用集合与泛型【概念】

ArrayList 允许重复、按插入顺序访问；HashSet 去重、无序；HashMap 键值对存储。泛型（如 List<Student>）在编译期约束元素类型，避免运行期强转异常。集合操作是 Java 开发的日常基础。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 13 节：集合与泛型

### 集合的选型与使用【步骤】

1) 需要有序可重复选 ArrayList，去重选 HashSet，键值映射选 HashMap；2) 用泛型声明集合元素类型；3) 遍历用增强 for 或迭代器；4) 删除元素用迭代器的 remove 避免并发修改异常；5) 统计前先过滤 null 元素。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 14 节：集合与泛型

### 集合易错点【易错点】

ConcurrentModificationException（遍历中修改）；泛型擦除导致运行时类型检查失效；把对象直接放入集合导致外部修改失控（应存副本）；HashSet 依赖 equals/hashCode 的正确实现。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 15 节：集合与泛型

### 成绩列表的统计与遍历【案例】

成绩管理用 List<Double> 存放有效成绩：add() 追加、增强 for 遍历求和、size() 取数量。排除缺考用 stream().filter(Objects::nonNull) 过滤。集合让同一份数据多次统计变得直接，避免手写数组扩容逻辑。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 12 节：集合与泛型（成绩管理示例）

### 数据层集合的使用规范【岗位应用】

真实项目里集合是数据流主力：查询结果用 List、去重用 Set、键值映射用 Map、栈/队列用 Deque。团队规范常限定：入参出参用接口类型（List 而非 ArrayList），避免把实现细节泄露给调用方。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 12 节：集合与泛型（岗位用法）

### 泛型约束与类型安全【规范】

泛型把类型错误从运行期提到编译期：List<String> 编译期阻止插入非 String。规范要求：集合一律声明泛型、不用裸类型（raw type）；方法级泛型明确上界（<T extends Number>）。1+X 考核包含集合与泛型基本应用。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 12 节：集合与泛型（规范）

### 集合中对象引用与不可变【安全】

把内部集合直接返回或暴露，外部可修改其内容绕过校验。安全做法：返回 Collections.unmodifiableList(内部副本) 或在 getter 里 clone；禁止把可变对象放入会被并发访问的共享集合而不做同步。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 12 节：集合与泛型（数据安全）

### List/Set/Map 怎么选【概念】

有顺序、可重复用 List（ArrayList 随机访问快、LinkedList 中间插入快）；不重复、快速去重用 Set（HashSet 无序、TreeSet 有序）；键值对应查找用 Map（HashMap 快、LinkedHashMap 保序）。选错容器是常见性能问题来源。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 12 节：集合与泛型

## 异常处理（KN_JAVA_EXCEPTION）

### 异常体系与处理【概念】

Java 异常分为检查异常（编译期强制处理）与运行时异常 RuntimeException（如 NullPointerException）。try-catch-finally 捕获处理；try-with-resources（try(...)）自动关闭实现了 AutoCloseable 的资源。异常处理要捕获具体类型而非笼统的 Exception。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 16 节：异常处理

### 规范的异常处理【步骤】

1) 先捕获最具体的异常类型；2) 需要释放资源用 try-with-resources；3) 记录异常信息并给出用户可理解的提示；4) 业务可恢复的错误用异常，参数校验失败应提前返回；5) 不要用空 catch 吞掉异常。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 17 节：异常处理

### 异常处理误区【易错点】

吞异常（空 catch）；捕获 Exception 掩盖具体错误；在 finally 中 return 覆盖异常；把业务分支当异常处理（性能与可读性差）；忽略空指针的预防（Objects.requireNonNull / 提前判空）。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 18 节：异常处理

### 空成绩集合的防御式处理【案例】

成绩统计必须防御空集合：scores 为 null 或 length==0 时提前返回或抛受控异常，不能直接遍历或除零。例如 averageScore() 先判空返回 0，或抛 IllegalArgumentException 提示无有效成绩，避免空指针与除零。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 16 节：异常处理（成绩管理示例）

### 异常与日志的岗位实践【岗位应用】

真实项目里异常要捕获-记录-转义：在边界记录日志（含异常栈与上下文），向上抛业务异常（如 ScoreNotFoundException）而不是底层细节；避免把堆栈直接返回给用户。日志级别区分 error/warn/info，异常信息要可定位问题。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 16 节：异常处理（岗位用法）

### 异常处理规范要点【规范】

规范要点：捕获最具体异常类型而非 Exception；try-with-resources 关闭资源；不在 catch 里空吞异常；不把业务分支当异常流（正常校验用 if 提前返回）；finally 不写 return 覆盖异常。这些是 CR 高频检查项。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 16 节：异常处理（规范）

### 异常信息不泄露敏感数据【安全】

异常消息与日志不得包含学号、成绩明细、SQL、密码等敏感信息（GB/T 35273 最小化原则）。错误提示对用户给可操作的说明（如成绩文件格式错误），完整细节只进服务端日志，防止信息泄露与攻击者探测。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 16 节：异常处理（数据安全）

### 受检异常与非受检异常【概念】

受检异常（IOException 等）编译期强制处理，体现调用方必须应对的失败；非受检异常（RuntimeException 如 NullPointerException、IllegalArgumentException）表示编程错误或可提前防御的问题。受检异常要处理或声明 throws，不能静默忽略。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 16 节：异常处理

## 输入输出流（KN_JAVA_IO）

### IO 流体系【概念】

字节流基类 InputStream/OutputStream 处理二进制数据；字符流 Reader/Writer 处理文本；BufferedReader 的 readLine() 按行读取文本；File 与 Path 描述文件路径。IO 操作必须正确关闭资源，防止句柄泄漏。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 19 节：输入输出流

### 按行读取文本文件【步骤】

1) 用 Files.newBufferedReader(Path) 或 new BufferedReader(new FileReader(...))；2) readLine() 循环读取直到返回 null；3) 每行做非空与格式校验；4) 用 try-with-resources 自动关闭；5) 捕获 IOException 并给出可读提示。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 20 节：输入输出流

### IO 易错点【易错点】

未关闭资源导致文件句柄泄漏；用 FileInputStream 按字节读文本导致中文乱码（应使用 Reader）；readLine 循环条件写错导致丢行；没有处理文件不存在/无权限的异常。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 21 节：输入输出流

### 读取成绩文件并统计【案例】

成绩导入场景：用 BufferedReader+FileReader 按行读取 CSV，每行解析为姓名+成绩，IOException 需处理，finally/try-with-resources 关闭流。读出的数据经集合过滤缺考后统计，实现文件到内存到统计的完整链路。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 19 节：输入输出流（成绩管理示例）

### 配置文件与日志的文件 IO【岗位应用】

真实项目 IO 多用于：读取配置（properties/yaml）、写日志文件、导入导出报表。规范：日志用日志框架（SLF4J+Logback）而非 System.out；配置文件走 classpath 资源；大文件用缓冲流逐行处理避免内存溢出。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 19 节：输入输出流（岗位用法）

### 字符集与编码规范【规范】

文本 IO 必须显式指定字符集，统一 UTF-8（Windows 下默认 GBK 易乱码）。规范要求：读写都声明 StandardCharsets.UTF_8；不要依赖平台默认编码；跨系统传输文件时声明编码与换行约定，避免成绩单乱码事故。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 19 节：输入输出流（规范）

### 文件路径与权限安全【安全】

文件操作的安全注意：路径不可信输入拼接会路径穿越（.. 跳出目录）；上传文件校验扩展名与大小；敏感文件（含成绩的导出）设置访问权限并加密存储；日志文件不记录完整个人信息。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 19 节：输入输出流（数据安全）

### try-with-resources 资源管理【概念】

try-with-resources（try (BufferedReader br = ...) {...}）自动调用 close()，杜绝资源泄漏；多个资源用分号并列。它要求资源实现 AutoCloseable。比 finally 手动关闭更安全（异常叠加不覆盖主异常）。

> 来源：《Java 核心技术·卷I》（原书第11版）Oracle Java 教程 · 第 19 节：输入输出流
