# WF04 错题优先个性化出题对接说明

## 1. 结论

错题本不再只是展示历史记录。正式生成下一道个性化练习前，知行课径后端会先查询当前学生、当前项目、当前知识点下仍为 `needs_review` 的错题，把其中未解决的细分错因作为 `learner_context.wrongbook_focus` 传给 WF04。WF04 必须围绕指定错因生成一题可追溯的迁移性变式题；如果没有待复习错因，才继续使用掌握度、可信度和独立证据进行常规推荐。

数据库仍由知行课径后端持有和写入，WF04 只读取本次请求中的错题焦点并返回增量事件，不直接连接或修改数据库。

## 2. 默认流程

```text
学生请求下一题
  -> 后端查询 wrongbook_items(status=needs_review)
  -> 有未解决错因：选出当前知识点下的优先错因
  -> 组装 learner_context.wrongbook_focus
  -> WF04 生成 variant 变式题
  -> 后端校验错因命中、概念命中、原题追溯、禁止原题复制
  -> 学生作答，WF04 返回错因增量
  -> 后端仅合并或消除本次覆盖的错因
  -> 仍有其他错因：保持 needs_review
  -> 所有错因均经独立作答验证：标记 improved_not_deleted，历史不删除
```

## 3. 后端传给 WF04 的关键字段

当后端命中待复习错因时，请求会自动改成：

```json
{
  "action": "generate_question",
  "question_role": "variant",
  "source_question_instance_id": "QUESTION-ROOT-001",
  "learner_context": {
    "practice_intent": "wrongbook_remediation",
    "wrongbook_focus": {
      "focus_source": "wrongbook",
      "active_wrongbook_count": 1,
      "knowledge_point_id": "KP-ARRAY",
      "source_question_instance_id": "QUESTION-ROOT-001",
      "root_question_instance_id": "QUESTION-ROOT-001",
      "original_question_title": "顺序表插入",
      "original_question_prompt": "原题题干",
      "target_error_points": [
        {
          "error_id": "ERR-...",
          "concept_id": "CONCEPT-BACKWARD-SHIFT",
          "criterion_id": "C-SHIFT",
          "expected_behavior": "明确从后向前移动",
          "root_cause": "混淆移动方向",
          "severity": "high"
        }
      ],
      "target_concept_ids": ["CONCEPT-BACKWARD-SHIFT"]
    }
  }
}
```

后端不会把学生原答案证据传给出题模型，避免题干泄露学生错误或答案；只传出题必需的错因、预期行为、根因和概念标识。

## 4. WF04 必须返回的内部字段

错题专项生成成功时，`question_spec` 必须包含：

```json
{
  "question_role": "variant",
  "source_question_instance_id": "QUESTION-ROOT-001",
  "target_error_point_ids": ["ERR-..."],
  "target_concept_ids": ["CONCEPT-BACKWARD-SHIFT"],
  "remediation_strategy": "说明新情境如何验证原错因",
  "generation_reason": "wrongbook_remediation",
  "variant_changes": ["更换情境", "更换参数"]
}
```

这些字段属于后端内部规格，不进入 `public_question`，学生看不到自己的错因标签和内部评分依据。

## 5. 评价与错题合并规则

`wrongbook_event` 使用“本次作答增量”语义：

- `attempt_error_points`：本次新增或仍然存在的错因。
- `candidate_resolved_error_point_ids`：仅当本次独立答对时，列出本题实际覆盖、可候选消除的错因 ID。
- `retain_unmentioned_error_points=true`：本次没有考到的历史错因必须保留。
- `wrongbook_delta_semantics=attempt_delta_only`：该事件不是整本错题本的完整快照。
- 使用提示或查看答案后的正确作答不算独立证据，也不能消除原错因。
- 独立答对一个目标错因，只消除该错因；同一原题仍有其他错因时保持 `needs_review`。
- 所有错因均被独立验证后，状态改为 `improved_not_deleted`，历史失败记录永久保留。

## 6. 学生自主权

错题优先是默认建议，不是强制门槛：

- 默认请求：后端自动优先待复习错因。
- 学生明确自主选题时传 `learner_context.practice_intent=student_selected`。
- 单次明确不使用错题优先时传 `wrongbook_priority=false`。
- 学生仍可换知识点、换难度、继续常规练习或退出。

## 7. 失败保护

以下情况拒绝题目入库并触发有界重试：

- WF04 未命中后端指定的 `error_id`。
- 有指定细分概念但题目没有覆盖相应 `concept_id`。
- 变式题复制原题题干。
- 题目没有保持 `source_question_instance_id` 追溯关系。
- 模型输出缺少针对性策略或变式变化说明。

重试后仍失败时，返回协议内错误，不写数据库，不产生掌握度证据。

## 8. 组员验收步骤

1. 先提交一份明确错误答案，确认错题状态为 `needs_review`，并至少产生两个细分错因。
2. 请求当前知识点下一题，抓取发往 WF04 的 JSON，确认 `practice_intent=wrongbook_remediation`、`question_role=variant`、原题 ID 与目标错因均存在。
3. 确认新题不是原题复制，且 `question_spec.target_error_point_ids` 命中请求目标。
4. 独立答对只覆盖其中一个错因的变式题，确认错题仍为 `needs_review`，另一个错因仍保留。
5. 再独立答对覆盖最后一个错因的变式题，确认状态变为 `improved_not_deleted`，历史作答事件仍可追溯。
6. 使用提示后答对，确认错因不被消除。
7. 传 `learner_context.practice_intent=student_selected` 或 `wrongbook_priority=false`，确认系统尊重学生选择，不强制出错题专项。

## 9. 文件职责

- `backend/domain.py`：错题查询、错因合并、精准消除与历史保留。
- `backend/server.py`：出题前注入错题焦点、后端质量门禁、评价字段透传。
- `frontend/agent.html`：优先展示具体错误根因或预期行为。
- 星辰 WF04 v1.3 YAML：请求校验、错因定向生成、评价错因结构化与自适应建议。
