# 知行课径：个性化自适应学习与纠错系统

## 项目简介

知行课径是一套面向职业教育学习场景的本地 Web 应用。系统接收测验或诊断系统传入的学习数据，结合学生的学习状态、薄弱知识点和教学偏好，提供连续学习引导、测验后纠错讲解与学习过程记录。

项目将可运行的前后端、学生状态持久化与讯飞星辰工作流整合在一起：未配置外部服务时可通过本地模拟模式完整演示；接入已发布工作流后，可切换为远程生成个性化教学内容。

## 解决的问题

传统的统一讲解往往难以回应学生当前的掌握情况。该系统围绕“诊断—学习—检验—纠错”的闭环，帮助学习者：

- 根据薄弱知识点进入有顺序的个性化学习路径；
- 按需切换讲解方式，查看示例、步骤、文本或视频资源；
- 在答错后获得基于错误证据的针对性讲解，并重做原题或练习变式题；
- 保存学习记录、讲解来源、偏好设置和收藏内容，便于持续学习。

## 核心能力

### 1. 学生画像与策略建议

后端会累计学习与纠错事件，并按阈值刷新学生画像。画像分析结果可用于形成默认教学策略；高频的学习请求则由本地策略引擎结合已保存的学习目标、薄弱点、路径和教学历史进行处理。

### 2. 连续学习个性化讲解

学习中心提供初始化学习、继续学习、切换讲解方式、查看示例与分步过程、请求视频或文本、理解检查等操作。系统会将工作流返回的教学包动态渲染为学习路径、课程内容、学习资源和阶段检查。

### 3. 测验后个性化纠错

上游提交已验证的错误测验结果后，系统可路由至纠错讲解流程。学习者能够查看错误证据和解释，补充信息后恢复中断的讲解，并从原题重做或同知识点变式练习中巩固掌握情况。

### 4. 可追溯的学习状态

系统使用 SQLite 保存学生状态、上游事件、工作流调用、学习周期、任务和题目实例、作答、讲解会话、结构化来源、通知、设置与收藏。上游事件以 `event_id` 去重，避免重复提交造成重复处理。

## 系统架构

```text
上游测验 / 诊断系统
        │ POST /api/upstream/assessment-result
        ▼
Python 后端服务
├── 状态中枢、策略引擎、知识依据缓存
├── SQLite 学习状态与调用记录
└── 工作流网关（mock 或讯飞星辰 OpenAPI）
        │
        ├── 学生画像分析工作流
        ├── 学习阶段个性化讲解工作流
        └── 测验后个性化纠错讲解工作流
        ▼
浏览器学习前端
├── 学习中心
├── 测验讲解
├── 学习记录
└── 偏好设置
```

## 技术组成

| 层级 | 实现 | 职责 |
| --- | --- | --- |
| 前端 | 原生 HTML、CSS、JavaScript | 呈现学习、纠错、记录与设置页面，并调用后端 API |
| 后端 | Python 标准库 HTTP 服务 | 提供业务接口、状态管理、工作流网关和静态资源托管 |
| 数据 | SQLite | 持久化学生学习状态与业务记录 |
| 智能流程 | 讯飞星辰工作流 / 本地 mock | 分别处理画像分析、学习讲解与纠错讲解 |
| 工作流资产 | YAML 与自定义节点代码 | 保存当前和历史工作流定义及教学包整理逻辑 |

## 快速开始

### 环境要求

- Python 3.11 或更高版本；
- 可访问本地 `127.0.0.1` 的现代浏览器。

后端运行时仅依赖 Python 标准库，默认启用 `mock` 模式，因此可以不配置外部密钥直接体验完整演示流程。

### 启动方式

在项目根目录运行：

```powershell
.\启动系统.ps1
```

或直接启动后端：

```powershell
python backend\server.py
```

然后打开 [http://127.0.0.1:4173/](http://127.0.0.1:4173/)。前端由后端托管，请勿直接通过 `file:///` 打开 `frontend/index.html`。

## 接入讯飞星辰工作流

如需使用远程工作流，请将 `backend/.env.example` 复制为 `backend/.env`，配置 API 凭据及三个已发布工作流的 ID，并设置：

```env
XINGCHEN_MODE=remote
XINGCHEN_PROFILE_FLOW_ID=学生画像分析工作流 ID
XINGCHEN_LEARNING_FLOW_ID=学习阶段个性化讲解工作流 ID
XINGCHEN_REMEDIATION_FLOW_ID=测验后个性化纠错讲解工作流 ID
```

在本地开发或演示环境中保留 `XINGCHEN_MODE=mock` 即可。密钥文件 `backend/.env` 已被忽略，不应提交到版本库。
