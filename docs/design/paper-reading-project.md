# 论文阅读辅助工具（未来独立项目 · 设计草稿 v0）

> 状态：2026-07-31 Ryan 决定作为**另一个独立项目**，暂不排期。
> 本文是灵感存档，不是 LearnFlow 的功能承诺。复用时按需取用，
> 不强依赖 LearnFlow 架构（但很多设计可借鉴：RAG/讲义生成/溯源/概念题）。

## 核心场景

辅助"读论文"全过程：接入 → 导读 → 精读 → 术语/背景 → 理解自测 → 多论文路线。

## 痛点清单（设计依据）

### 门槛类
1. 术语爆炸：一篇 30+ 陌生术语，查完上下文丢失，论文不解释只引用
2. 背景缺失："as in [12]"——方法建立在前作之上，需暗中补 3-5 篇背景
3. 公式跳步："不难看出"对你很难看出；论文数学是压缩的，不是教学的
4. 英文长句：非母语阅读速度减半，注意力耗在句子解析上

### 认知类
5. 被动阅读：从头读到尾平均用力，读完整篇说不出解决了什么问题
6. 读完就忘：无主动提取，留存率 ~10%
7. 方法 vs 动机混淆：记住步骤，说不出"为什么这么设计、解决什么缺陷"
8. 不会略读：不知道哪节精读哪节扫读

### 信息组织类
9. 笔记散乱：划线/标签/本地笔记互不关联不可检索
10. 溯源断裂：概念眼熟，想不起出处
11. 多论文失联：每篇孤立，理不清谁依赖谁、谁改进谁（研究地图缺失）

### 验证类
12. 看懂≠学会：唯一检验是复述/回答为什么/应用，无自测环节
13. 对实验数字不批判：结论 vs 证据强度不分

### 筛选类
14. 值不值得读：需 5 分钟判断（问题/结论强度/相关性）

## 功能设计（按痛点对应）

### P0 论文接入
- arXiv 链接 / PDF 上传；arXiv API 拉元数据（标题/摘要/作者）
- PDF 解析（pymupdf）→ 按论文结构分块（摘要/引言/方法/实验/结论）
- 图表提取 → OCR caption → 进 RAG（借鉴 LearnFlow T6 图片管线）

### P1 论文导读讲义（治 5/6/7/8）
一键生成，非复述：
- 研究问题是什么 / 为什么重要
- 方法核心直觉（一句话版）
- 关键实验结论
- 与已学知识的关系
- 建议阅读顺序（哪些精读、哪些扫读）

### P2 逐节精读（治 3/7）
每节生成：方法动机、公式直觉（LLM 用 KaTeX 重推，不依赖 PDF 提取 LaTeX）、
与前后节逻辑衔接。

### P3 术语卡 + 背景链（治 1/2/10）
- 高频/陌生术语 → 术语卡（定义+直觉+出现位置）
- Related work → 检索已有知识库：有则"去学哪一节"，无则提示补充

### P4 理解自测（治 12/13）
概念题（复用 LearnFlow 概念题生成思路）：复述动机、结论与假设关系、
"为什么能 work"。

### P5 多论文阅读路线（治 11）
按引用依赖/主题递进排序成阅读路线。

### 双栏阅读模式（承载 UI）
左：论文原文 PDF（划词）｜右：导读/精读/术语卡/自测
（借鉴 LearnFlow LectureRenderer + BottomWorkspace，布局左右分栏）

## 技术增量点
- PDF 解析、arXiv API
- paper-logic 分块模板
- 双栏阅读 UI
- （其余：RAG/检索/溯源/笔记/进度/概念题全部可借鉴 LearnFlow 已验证的方案）

## 优先级建议
导读（P1）→ 术语卡+背景链（P3）→ 理解自测（P4）→ 多论文路线（P5），
双栏是地基，PDF 接入是前置。
