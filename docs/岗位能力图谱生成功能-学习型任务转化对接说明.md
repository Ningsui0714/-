# 岗位能力图谱生成功能 → 学习型任务转化功能对接说明

版本：`1.0`  
交接协议：`competency-graph-learning-task-handoff-v1`

## 1. 对接目标

岗位能力图谱生成功能在用户选中一项**已经确认的企业典型工作任务**后，将该任务的简介、强相关知识点、强相关技能点以及知识—技能特殊关系交给学习型任务转化功能。

学习型任务转化功能负责继续生成实际作业步骤、阶段产物、检查点、安全边界和步骤级知识—技能映射。它不会把输入替换成相似岗位，也不会在交接阶段生成课程章节、学习目标或个性化学习路径。

> 输入必须是一项企业真实工作任务，例如“交换机 VLAN 配置与连通性验收”，不能只传“网络工程师”这样的岗位名称。

## 3. 调用接口

在 LearnFlow 内对接时统一调用：

```text
POST /api/learning-task-conversion/upstream-handoffs
Content-Type: application/json
```

接口复用当前 LearnFlow 登录态。浏览器请求必须携带同源 Cookie：

```ts
const response = await fetch('/api/learning-task-conversion/upstream-handoffs', {
  method: 'POST',
  credentials: 'include',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(handoff),
})

if (!response.ok) throw new Error(await response.text())
const result = await response.json()
```

独立任务服务的同名接口为：

```text
POST /api/v1/learning-task-conversion/upstream-handoffs
```

团队集成时优先使用 LearnFlow 的 `/api` 接口，不要让浏览器直接依赖任务服务器地址。

## 4. 请求字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `schema_version` | string | 是 | 固定为 `competency-graph-learning-task-handoff-v1` |
| `upstream_task_id` | string | 是 | 上游任务稳定 ID，后续不得复用给其他任务 |
| `correlation_id` | string | 是 | 本次交接链路 ID，用于追踪和幂等识别 |
| `task_name` | string | 是 | 单个企业典型工作任务名称 |
| `task_brief` | string | 是 | 不少于 10 个字符的任务简介，说明对象、动作和结果 |
| `source_context` | object | 否 | 产业、岗位、工作情境、预期产物等来源上下文 |
| `knowledge_points` | array | 是 | 1～30 个强相关知识点 |
| `skill_points` | array | 是 | 1～30 个强相关技能点 |
| `relations` | array | 是 | 1～100 条知识—技能特殊关系 |

知识点字段：

```json
{
  "knowledge_id": "稳定且唯一的知识点ID",
  "name": "知识点名称",
  "description": "该知识在本任务中的具体范围"
}
```

技能点字段：

```json
{
  "skill_id": "稳定且唯一的技能点ID",
  "name": "技能点名称",
  "observable_action": "能够被观察和验收的岗位动作"
}
```

关系字段：

```json
{
  "relation_id": "稳定且唯一的关系ID",
  "knowledge_id": "必须引用knowledge_points中已声明的ID",
  "skill_id": "必须引用skill_points中已声明的ID",
  "relation_type": "required_for_step",
  "strength": "high",
  "reason": "说明知识如何支撑具体技能动作和可观察结果",
  "applies_to_steps": ["适用的任务阶段或步骤"]
}
```

`relation_type` 允许：

- `prerequisite`：执行技能前必须具备的知识；
- `required_for_step`：知识直接支撑某一步技能动作；
- `enables`：知识使技能可以迁移到当前工作情境；
- `verifies`：知识用于判断技能结果是否合格；
- `safety_constraint`：知识用于约束技能动作的安全边界。

正式交接建议只发送 `critical` 或 `high` 关系。`medium`、`low` 会被记录为需要修正的非强关系。

## 7. 成功响应与反向反馈

提交后会立即返回语义校验结果，不需要解析自然语言。上面的完整实例会得到类似以下成功响应：

```json
{
  "handoff_id": "t2h_1234567890abcdef",
  "status": "accepted",
  "feedback": {
    "schema_version": "learning-task-conversion-feedback-v1",
    "handoff_id": "t2h_1234567890abcdef",
    "correlation_id": "competency-to-task-20260817-001",
    "upstream_task_id": "network_vlan_001",
    "status": "accepted",
    "requires_revision": false,
    "accepted_relation_ids": [
      "rel_vlan_config_001",
      "rel_vlan_acceptance_001"
    ],
    "rejected_relation_ids": [],
    "issues": [],
    "summary": {
      "knowledge_point_count": 2,
      "skill_point_count": 2,
      "relation_count": 2,
      "strong_relation_count": 2,
      "issue_count": 0
    }
  }
}
```

状态含义：

- `accepted`：全部强关系可直接用于任务步骤映射；
- `accepted_with_feedback`：任务已接收，但部分关系需要上游修正；
- `rejected`：没有关系通过门禁，需要修正后重新提交。

上游应保存 `handoff_id`、`correlation_id` 和反馈。修正时生成新的 `correlation_id` 再提交，不能直接覆盖已经产生的历史记录。

该接口成功表示“上游事实与关系已经被任务转化功能接收”，不等同于最终学习型任务已经生成。上游前端收到 `accepted` 或 `accepted_with_feedback` 后负责切换到学习型任务转化场景，并将 `handoff_id` 保存在本次场景上下文中；最终任务页以任务转化功能返回的 `task_card_id` 为准。

## 8. 常见错误

| HTTP 状态 | 原因 | 处理方式 |
|---:|---|---|
| `401` | 未携带 LearnFlow 登录态 | 使用同源请求并设置 `credentials: 'include'` |
| `422` | 字段缺失、类型错误或协议版本错误 | 按本文件模板修正请求体 |
| `502` | 后端任务服务返回异常 | 保留 `correlation_id`，提示用户稍后重试 |

以下内容会进入语义反馈而不是被系统猜测修复：

- 关系引用不存在的知识点或技能点；
- 关系强度不是 `critical`/`high`；
- 关系理由只有“相关”“需要掌握”等套话；
- 知识点或技能点没有进入任何通过校验的关系。

## 9. 联调验收清单

- [ ] 点击的是单个企业典型工作任务，不是岗位名称。
- [ ] 每次交接都有唯一 `upstream_task_id` 和 `correlation_id`。
- [ ] 知识点、技能点和关系都使用稳定 ID。
- [ ] 每条关系引用的知识点和技能点均已在本包声明。
- [ ] 每条正式关系强度为 `critical` 或 `high`。
- [ ] 前端根据 `status` 和 `feedback.issues` 展示接受或修正结果。
- [ ] 不依赖 PDF/JSON 下载按钮，直接通过接口交换结构化数据。
