# 摘要

教育是大语言模型最有前景的现实应用之一。然而，当前 LLM 主要依赖静态预训练知识，难以适应不同学习者；一般 RAG 系统虽然能够补充资料，却不足以提供持续、个性化且有引导性的反馈。

为弥补这一缺口，作者提出 DeepTutor：一个完全开源的智能体框架，将**具有引用依据的问题辅导**与**按学习者难度校准的练习题生成**统一起来。系统的混合个性化引擎把静态知识依据与动态学习者记忆结合，使每一次交互都能根据学生不断变化的需求进行调整。

同一个个性化底座还被扩展到自适应学习流程、互动教材和主动式多渠道辅导 Agent。为了评价个性化辅导，作者构建 TutorBench：一个基于五个学科领域大学课程材料、包含定制学习者画像的交互式 benchmark。论文还提出第一人称交互评测协议，让由画像驱动的学生模拟器直接参与辅导过程。

作者报告：在个性化指标上，DeepTutor 平均提高约 `10.8%`；在五类 backbone 模型的通用智能体推理实验中，平均相对增益约为 `29.4%`。论文同时提供人类偏好对齐和组件消融实验。

> 译注：`10.8%` 指 TutorBench 十项 rubric 综合质量相对 Naive Tutor 的提高；不是现实学生考试成绩或长期学习增益提高 `10.8%`。

# 1. 引言

教育是部署大语言模型时影响深远、发展迅速的现实领域。有效的人类教师不只是给出正确答案，还会诊断误解，根据学习者水平搭建解释支架，并持续安排有针对性的练习，把薄弱点逐步转化为优势。LLM 已能进行流畅的教育对话，但如何在统一、自适应的系统中同时实现这些紧密关联的教学能力，仍是开放问题。

现有方法通常分别处理问题的不同部分，如 Figure 1 所示。

在问题辅导方向，近期工作已经不再满足于直接生成答案，而是开始评价开放式教学行为、诊断学生推理错误，并让模型更倾向于引导式问题求解。虽然回答更有针对性，但诊断结果通常只在当前辅导回合内使用。

在练习题生成方向，LLM 方法会通过规划或自我修订控制题目内容、难度和教学目标。这提高了题目质量，但生成过程一般由预定义目标驱动，而不是由学生近期的辅导轨迹驱动。

因此，两类流程仍然局限在各自任务内部：

- 辅导轨迹不会决定下一道练习题。
- 练习表现不会更新未来的解释方式。
- 系统至多维护粗粒度技能清单，而不是能揭示学生“怎样出错”的推理轨迹。

论文认为，这些问题具有同一个根源：系统缺少细粒度、持续演化的学习者模型。

除此之外，还存在评测缺口。多数教育 benchmark 采用教师中心视角，检查 LLM 是否遵循教学原则、答案是否正确，却把学生当作通用的信息接收者。少数考虑学生差异的工作也通常只提供与具体课程材料脱节的粗粒度熟练度标签。因此，一个系统能否在多轮对话中真正适应某个具体学习者，长期以来没有得到充分检验。

作者主张，解决系统与评测的双重缺口，需要建立闭合的交互循环：问题辅导中暴露的薄弱点应直接影响下一步生成什么题；学习者在这些题目上的表现，又应反过来更新用于未来解释的学习者模型。

实现这一循环需要两个条件：

1. 一种结构化记忆，保存细粒度交互历史，而不仅是标量技能分数。
2. 一个统一系统，使各个模块共享并持续更新同一份记忆。

DeepTutor 通过共享个性化引擎统一问题辅导和练习题生成。两条管线由 Trace Forest 连接。专门的记忆 Agent 持续从分层交互轨迹中提炼学习者画像，使每次交互都能影响下一次交互。

为评价这种能力，作者构建 TutorBench。每个条目同时包含基于资料的学习者画像、知识缺口和交互式辅导任务；第一人称学生模拟器参与多轮对话，从端到端角度测试系统的适应行为。

## Figure 1 译文

**从彼此隔离的教育流程走向闭环个性化辅导。**以往的问题辅导 Agent 和练习题生成 Agent 只在各自任务内部运行；DeepTutor 使用由 SKG 和 DPM 组成的混合个性化引擎，在辅导轨迹与个性化练习之间形成闭环。

## 论文贡献

1. 提出开源的 DeepTutor 智能体辅导框架，通过共享学习者上下文连接引用可溯源的问题辅导和按难度校准的练习题生成。
2. 设计结合 SKG 与 DPM 的混合个性化引擎，利用 Trace Forest 将多轮交互提炼为细粒度、可复用的学习者画像。
3. 说明同一个个性化底座怎样扩展到更广泛的自适应学习流程、互动教材和主动式多渠道辅导 Agent，同时将这些系统扩展与定量评测的核心辅导模块区分开。
4. 构建 TutorBench，通过五个大学学科领域的第一人称交互评测，验证 DeepTutor 的个性化辅导质量、跨领域能力和跨 backbone 泛化能力。

# 2. DeepTutor 框架

## 2.0 总览

Figure 2 展示了 DeepTutor 如何通过共享的 Hybrid Personalization Engine 统一两种任务：

- **问题辅导**：针对学生问题 `q`，生成具有引用依据并按学习者水平校准的指导 `a`。
- **练习题生成**：针对主题 `tau`，生成面向学习者知识缺口的定制练习。

系统把课程知识 `K` 与持续演化的学习者画像组合：

`D = (D_s, D_w, D_r)`

在每个 Agent 步骤之前，系统组装个性化记忆上下文 `C_mem`。问题辅导依次执行调查、引导式求解和迭代写作；练习题生成则把想法选择与经过验证的题目-答案-解释构造分开。每次交互结束后，系统更新画像和轨迹历史，从而形成闭环。

## Figure 2 译文

**DeepTutor 总览。**SKG 提供课程上下文，DPM 提供学习者上下文。混合个性化层同时服务问题辅导和练习题生成。完成的交互会更新 Trace Forest 与学习者画像，构成闭合的辅导循环。

## 2.1 混合个性化引擎

两条管线都需要两种互补上下文：领域知识与学习者认知。DeepTutor 用 SKG 提供前者，用 DPM 提供后者，再通过画像注入机制为不同角色组装不同上下文。

### 2.1.1 静态知识依据

为了处理包含文本、图像、表格等异构内容的真实课程材料，系统首先将源文档分解为原子内容单元，并尽量保留模态结构。

随后建立两种互补索引：

- 知识图 `G`：组织内容单元之间的结构关系和上下文关系。
- 稠密索引 `B`：使用编码器把所有内容单元投影到 embedding 空间。

`G` 与 `B` 共同构成课程知识 `K` 的双索引检索底座。查询时，图遍历负责发现显式关系，稠密检索负责发现语义相似内容。两组候选结果通过 Reciprocal Rank Fusion 融合，再进行去重和上下文预算截断，最终得到领域依据 `C_rag`。

> 译注：这里的知识图主要服务课程资料检索。论文没有把它定义成会根据就业市场证据自动更新的岗位能力图谱。

### 2.1.2 动态个人记忆

知识库描述课程教什么，动态记忆描述某个学习者怎样接触和理解这些内容。

该模块的核心是 Trace Forest `F`。其中每棵树记录一次完整辅导交互，并且能够以不同粒度进行语义检索。节点分为三层：

| 层级 | 保存内容 |
|---|---|
| Level 1 | 会话级输入和全局摘要 |
| Level 2 | 任务分解形成的中间规划单元 |
| Level 3 | 工具输出、证据、验证结果等细粒度执行记录 |

每个节点都带稠密 embedding，因此能够在整个森林中做相似度检索。这种设计借鉴了把长期上下文外部化、按照工作流或交互轨迹组织经验的 Agent 记忆研究。不同任务在各层使用的具体节点类型并不完全相同。

Trace Forest 不是被动存储。系统通过 TraceToolkit 提供三个抽象操作：

- `SearchTrace`：在 `F` 中进行语义近邻检索。
- `ListTraces`：按时间、任务类型或主题筛选轨迹。
- `ReadNodes`：读取完整节点内容和祖先路径。

任何 Agent 都可以根据自己所需的粒度探索学习者历史。

#### 学习者画像构造

Trace Forest 提供可分析的证据空间，但画像不是对最近一次交互的被动摘要。每当产生新轨迹，三个专门的记忆 Agent 会主动使用 TraceToolkit：检索相关历史会话，在必要时读取细粒度节点，再将当前行为与跨会话模式比较，最后更新：

`D = (D_s, D_w, D_r)`

- `D_s`：会话历史，包括学习主题、解题路径和表现趋势。
- `D_w`：以证据为依据的薄弱点清单，包括反复困惑、错误答案模式、活跃或已解决的知识缺口。
- `D_r`：用于指导未来交互的教学自我反思。

因此，画像构造是一种由工具支持的分析过程，而不是一次性的文本摘要。作者希望借此让个性化建立在可观察轨迹上，而不是粗粒度潜在掌握分数上。

每个 Agent 执行前，系统通过两个渠道构造 `C_mem`：

1. 主动轨迹检索：TraceToolkit 找出最相关节点，并在三层之间分配检索预算，兼顾会话全貌和细粒度先例。
2. 角色相关画像摘取：根据 Agent 功能路由不同的 `D` 片段。例如 Planner 接收 `D_s` 与 `D_w`，Writer 接收 `D_r`，生成 Agent 接收 `D_w` 和历史题型。

总 token 预算还会在 `C_rag` 与 `C_mem` 之间动态分配。

## 2.2 个性化问题辅导

已有工具增强 Agent 往往把规划、检索和回答写作放进同一个推理循环。这对短事实问题可能足够，但在辅导场景中，充分调查和个性化表达会竞争同一个上下文窗口。

受到教学支架理论启发，DeepTutor 把问题辅导拆为三个阶段：先调查，再逐步引导求解，最后自适应写作。

### 阶段 1：个性化调查

Planner 在承诺某个计划之前，先进行轻量调查。它把 `q` 分解为若干 meta-question，并从以下位置收集证据：

- 课程知识 `K`，通过 RAG。
- Trace Forest，通过 TraceToolkit。
- 必要的辅助工具。

结合 `C_rag` 与 `C_mem` 后，Planner 生成具体且带注释的子目标计划：

`P = <s_1, ..., s_K>`

“先调查再规划”使子目标能够针对学习者的真实缺口。例如，计划可以写成“复习三角函数中的链式法则”，而不是笼统地写“复习微积分”。

### 阶段 2：逐步引导式求解

Solver 对每个子目标 `s_k` 先分析，再调用工具并记录笔记。为了控制不断增长的推理上下文，系统采用三个机制：

- **self-notes**：把每一步结果压缩为后续步骤可引用的短结论，避免重复携带冗长中间过程。
- **hierarchical compression**：逐步把完成的子目标压缩成摘要，为后续深入推理腾出容量。
- **adaptive replanning**：当前计划不足时，修订尚未完成的子目标，同时保留已经完成的工作。

### 阶段 3：基于证据的迭代写作

Writer 不直接拼接原始工具输出，而是从 scratchpad 中抽取结构化证据，通过多轮修订构造回答，并协调可能冲突的发现。

`C_mem` 同时控制解释深度和语气，使内容更接近学习者的最近发展区：初学者获得逐步推导和支架，熟练学习者获得突出关键洞察的简洁总结。外部事实性主张要带有可追踪引用，通常来自课程知识 `K`，启用时也可来自外部网页证据。

## 2.3 个性化练习题生成

Tutor 不仅要回答问题，还要提出正确的问题：题目应当有意义、事实有依据，并适合当前学习者。

DeepTutor 将题目生成拆成两个阶段，把“问什么”与“怎样生成并验证”分离。

### 阶段 4：个性化题目想法生成

Idea Agent 不从一个裸主题直接写题，而是围绕主题 `tau`，结合个人学习情况绘制概念空间。它读取：

- `C_rag` 与 `C_mem`。
- 历史错误。
- 难度趋势。
- TraceToolkit 找到的相关旧题。

每个候选想法包含目标概念、题型（选择题、书面回答或编程题）以及以已诊断缺口为依据的个性化理由。

Evaluator 根据清晰度、相关性和多样性反复筛选、排序和删除错误或重复想法，得到结构化题目模板 `{T_i}`。

### 阶段 5：Critic 引导的题目-答案-解释生成

Generator 根据每个模板生成三元组：

`(q_i, a_i, e_i)`

其中 `q_i` 为题目，`a_i` 为答案，`e_i` 为解释。`C_rag` 提供事实依据，`C_mem` 用于难度校准。

独立的 Validator 执行两类检查：

1. LLM 检查：模板一致性、事实正确性和教学合理性。
2. 计算检查：编程或计算题还要在沙箱中执行代码。

Validator 不共享 Generator 的推理链，因此必须独立验证正确性，减少自我评价沿用同一错误推理而产生的“自证”风险。失败项会得到结构化诊断反馈，并重新生成，直到同时满足教学与事实约束。

## 2.4 闭环辅导循环

每次交互结束后，系统向 `F` 添加一棵新轨迹树，三个记忆 Agent 并行更新 `D`。更新后的画像立即服务下一次会话。

闭环的关键是两种任务之间的双向耦合：

- 问题辅导诊断出的薄弱点进入 `D_w`，直接影响下一步生成哪些题。
- 学习者在生成题目上的表现更新 `D_s` 和 `D_r`，改进未来解释。

由于每个 Agent 都能使用 TraceToolkit 查询轨迹森林，反馈不仅存在于画像摘要中，还能够追溯到任意旧交互的细粒度节点。作者认为，随着历史增长，这能产生越来越细致的个性化。

> 译注：这里的“自我强化循环”是记忆和上下文层的反馈循环，不等同于用奖励更新模型参数的强化学习。

# 3. 个性化底座的扩展

前一节讨论的是论文定量评测的核心：引用可溯源的问题辅导、个性化练习题生成和学习者记忆更新。现实学习还包括跨来源综合、构造不同表征、通过写作外化理解，以及在较长时间内回顾薄弱概念。

如果每种活动都有独立工具和学习者模型，个性化上下文仍会碎片化。因此，作者把混合个性化引擎设计为可复用底座：同一 Agent loop、跨界面记忆、可插拔知识库、技能和外部 Subagent 共同服务不同学习活动。

## 3.1 从辅导流程到自适应学习

### Deep Research

Deep Research 用于开放式知识综合。它重写学习者请求、分解研究方向，并行调用课程资料、网页、论文搜索和计算工具，最终汇总为结构化报告。研究轨迹也可成为学习者兴趣、反复困惑和新知识目标的证据。

### 外部专业能力

My Agents 可以在当前回合咨询运行于学习者设备或外部环境中的 Agent，例如 Claude Code、Codex 或 Partner，也可以导入这些 Agent 的历史 transcript 作为第一人称参考。系统以有界次数调用外部 Agent，把返回内容当作证据，最后仍由 Tutor 用自己的语言作答。

### Visualize 与 Math Animator

当目标概念具有结构性、过程性或几何性时，纯文本可能不足。Visualize 和 Math Animator 把“选择什么表征”视为教学动作：分析目标与对话上下文，生成图、表、动画或互动演示，再在返回学习者前进行审查。

### Co-Writer

Co-Writer 是 Markdown 编辑工作区，而不是另一种聊天流程。学习者直接操作文档与选区，AI 可以在课程或网页依据下执行重写、扩展、缩写和重组，并以可接受或拒绝的 diff 返回。写作中的省略、不稳定术语和因果连接不足，可以成为新的学习证据。

### Mastery Path

Mastery Path 把一个主题转化为跨会话的学习计划。步骤会被排序、评分和重新安排；每次尝试都根据参考答案评分，更新薄弱概念 `D_w`，并交给调度器决定复习内容和时间。练习来自同一题目生成能力，因此辅导历史和掌握进度不会分离。

> 译注：论文正文只从系统层描述 Mastery Path，没有在主实验中验证其长期掌握估计或路线规划效果。

## 3.2 通过底座复用构建互动教材

Book Engine 把个别工作流提升为课程化产物。它将来源、旧交互、笔记和题目整理为持久学习环境，而不是只生成一次回答。

### 输入快照与提案

流程不是只根据标题生成教材，而是先冻结多来源上下文，包括用户意图、聊天历史、Notebook、知识库、题目类别和题目条目。Ideation 阶段生成范围、受众、教学目标和预期结构提案，用户确认后才进行昂贵编译。

### 课程脊柱与概念图

来源探索 Agent 对选定材料进行检索，Spine Synthesizer 在页面生成前建立章节结构和概念图，显式表示先修关系与主题覆盖。这里把核心辅导中的来源依据原则，从单次对话扩大到课程路径。

### 块级页面编译

每页由一系列类型化 block 组成，而不是一篇整体长文。可用类型包括正文、提示块、测验、图、互动演示、动画、代码、时间线、闪卡、深入阅读、章节总结和概念图等。不同能力为教材提供不同产物：Research 提供证据，Visualize 提供表征，Question Generation 提供自测，Co-Writer 支持学习者笔记。

### 持久交互与补救

编译后仍可单独重生成或插入 block，也可以围绕某个概念创建深入子页。每页有独立聊天，测验会更新访问、书签、得分和薄弱章节。系统还对来源生成 fingerprint，在知识库变化时标记可能过时的页面。

## 3.3 主动式多渠道辅导

前述功能仍主要由学习者主动启动，而长期学习还需要及时复习和低摩擦跟进。Partners 把同一套能力放入持久、多渠道的 Agent 实例。

每个 Partner 有自己的工作区、会话状态、persona、skills 和长期记忆，但共享 DeepTutor capability 层。消息适配器把网页或即时通讯消息转换为统一的 orchestrator 上下文。

Partners 不重新实现辅导行为。其 skill 描述何时以及怎样调用解释、解题、出题、研究、可视化、文档交互和调度等动作。Heartbeat 与 scheduling 层可以周期性判断是否需要提醒学习者复习薄弱点、延迟生成复习任务，或汇总新增资料。

论文将 Partners 定位为长周期个性化辅导的部署机制，而不是本次 benchmark 已验证的干预。其对保持率、参与度、打扰成本和真实学习结果的影响仍需纵向研究。

# 4. TutorBench

现有教育 benchmark 往往只检查回答正确性，或用通用画像评估教学原则，难以测量跨多轮对话形成的个性化。因此作者构建 TutorBench。

每个 TutorBench 条目包含：

- 学习者画像。
- 有资料页码依据的知识缺口。
- 会在对话中暴露这些缺口的交互任务。
- 对应来源材料。

## 构造流程

1. 将大学课程资料转化为知识库。
2. 根据材料生成不同水平和背景的学习者画像。
3. 从指定来源页提取并构造知识缺口。
4. 生成能自然暴露缺口的交互任务，通过 rejection sampling 筛选。

## 数据统计

TutorBench 使用 30 个知识库，覆盖 humanities、sciences、engineering、business 和 frontier research 五类领域。

每个知识库生成三个不同水平的学生画像，共 90 个画像。每个画像在 rejection sampling 后保留三个任务，共 270 个任务。所有条目由人工复核。

任务类型包含概念理解、问题求解、应用和比较。每个条目包含三个明确落到来源页码的知识缺口。

# 5. 实验

论文从五个方向评价 DeepTutor：

1. 第一人称交互评测。
2. 跨领域泛化。
3. 人类偏好对齐。
4. 组件消融。
5. 通用智能体问题求解迁移。

定量实验集中在闭环辅导核心。互动教材和 Partners 的纵向效果留给未来工作。

## 5.1 第一人称交互评测

单轮指标难以覆盖多轮中的诊断和补救。TutorBench 因此让 LLM 学生模拟器直接与 Tutor 对话，再依据个性化 rubric 评分 transcript。

一个 benchmark 条目初始化画像、知识缺口、任务和资料。模拟器把知识缺口转换为第一人称信念，进行多轮辅导，最后请求个性化练习。动态缺口节奏使模拟学生能够表现出坚持错误信念、部分接受纠正等行为，而不是立即同意 Tutor。

### 十项指标

教学侧每轮评分：

- `SF` Source Faithfulness：事实、术语、资料依据和引用是否与来源一致。
- `PER` Personalization：是否真正回应当前学习者的困惑和会话轨迹。
- `APP` Applicability：指导是否具体、可立即执行和验证。
- `VID` Vividness：是否有效使用结构、公式、表格、代码等多种表征。
- `LD` Logical Depth：是否提供显式因果链和中间推理，而不是只给结论。

练习侧每次会话评分：

- `FIT` Fitness：题目是否针对诊断出的弱点，难度是否适合。
- `GND` Groundedness：题干、答案和解释是否有来源依据。
- `DIV` Diversity：题目角度和认知操作是否多样。
- `ANS` Answer Quality：正确选项、解释和干扰项是否可靠。
- `CC` Cross Concept：是否要求综合会话中多个概念，而不是孤立记忆。

所有指标使用 1-5 分。每份 transcript 由固定 Judge 独立评分三次后取平均。

主实验使用 Gemini-3-Flash 作为学生模拟器及全部 Tutor 的 backbone，包括 DeepTutor；Claude Sonnet 4.6 作为温度为 0 的 Judge。完整结果来自 270 个任务、90 个画像和 30 个知识库。

### 基线

- Naive Tutor：直接提示。
- CoT Tutor：加入逐步思考。
- Self-Refine Tutor：增加教学审查与修订步骤。
- ReAct Tutor：使用 thought-act-observe 推理循环。

四个基线与 DeepTutor 使用相同 backbone 和 RAG 接口。

作者认为，单独加入 CoT、自我修订或 ReAct 工具循环，并不足以获得 DeepTutor 的学习者适应行为。DeepTutor 在 Vividness、Personalization 和 Logical Depth 上提升明显，与“先调查、再求解、最后自适应写作”的结构相符。

练习侧的 Groundedness、Diversity 和 Cross Concept 提升较大；Fitness 与 Answer Quality 的提升较小，但仍显示题目更加针对弱点且经过验证。

## 5.2 跨领域泛化

五个领域之间的 Overall Quality 最大相差 `0.16` 分，说明结果不是由单一学科驱动。十项指标的平均跨领域跨度为 `0.36` 分，其中 Source Faithfulness 波动最大，表明证据引用比学习者适应更受领域影响。

教学侧的 Personalization、Applicability、Vividness 和 Logical Depth 较稳定；Source Faithfulness 是主要瓶颈。练习侧 Answer Quality 最强，Groundedness 最弱，说明生成正确题目相对容易，让题目和解释都明确回到来源更困难。

## 5.3 人类偏好对齐

作者在 45 个领域分层会话上进行盲测，每个领域 9 个。人类标注者比较相同画像、任务、资料和模拟协议下的 DeepTutor 与 Naive Tutor 输出。

在十项指标上，人类和 LLM Judge 都把最大偏好份额给 DeepTutor，尤其是 Personalization、Vividness 和 Diversity。二者在十个指标的 DeepTutor 胜率上具有较强相关：

- Pearson `r = 0.82, p = 0.0038`
- Spearman `rho = 0.83, p = 0.0027`

这说明自动 Judge 对不同指标优劣的排序与人类判断大体一致，但该实验评价的是输出偏好，不是学习增益。

## 5.4 消融实验

作者分别移除 SKG、DPM 或两者都移除。

- 移除 SKG：Groundedness 下降最大，其次是 Source Faithfulness 和 Cross Concept。解释和题目缺少课程证据后，事实锚定和跨资料关联受损。
- 移除 DPM：Personalization 和 Fitness 下降最明显。学习者画像对解释适配和难度校准至关重要。
- 同时移除：整体退化最大。

作者据此认为：SKG 主要约束 Tutor“说什么”，DPM 主要影响 Tutor“怎样适应学习者”，两者互补而非可以互换。

# 6. 相关工作

## 个性化与记忆

LLM 个性化研究包括反思式对话摘要、累积用户模型、RAG 适配、工作流归纳和分层 Agent 记忆。经典学习者建模则从 BKT 延伸到神经网络和记忆增强的知识追踪模型。

DeepTutor 结合两条研究路线，提出面向辅导场景的树结构动态记忆，使交互轨迹在多个粒度上保持可搜索。

## 教育人工智能

相关工作涉及带学生建模的对话 Tutor、多 Agent 教学架构、开源教育平台、对话式学习诊断、知识追踪增强的推荐，以及通过强化学习进行教学对齐。

MathTutorBench 等 benchmark 已开始评价开放式教学质量，但基于个体材料、连接辅导与出题的自适应闭环仍研究不足。DeepTutor 的区别是让解释和练习题生成共享同一学习者模型，并从学生中心视角评价闭环。

# 7. 结论

论文提出 DeepTutor：一个连接引用可溯源辅导、按难度校准的练习题生成和混合个性化引擎的智能体式个性化辅导框架。

作者还提出 TutorBench，通过基于来源的画像、第一人称学生模拟器和个性化 rubric 评价多轮辅导。在 TutorBench 上，DeepTutor 的 Overall Quality 相对提高约 `10.8%`，五个领域表现较稳定，人类与 LLM Judge 的偏好趋势一致。

在关闭个性化引擎的通用求解迁移实验中，investigate-solve-write 管线在五类 backbone 上取得平均约 `29.4%` 的相对增益。消融实验支持知识依据和学习者记忆在“说什么”与“怎样适应”方面的互补作用。

作者认为，同一底座还可以支持自适应学习流程、互动教材和主动式多渠道 Agent，为从 benchmark 辅导管线走向长周期个性化学习系统提供实践基础。

# 局限

论文承认以下局限：

1. 交互评测依赖 LLM 学生模拟器与 rubric Judge，受控模拟与真实学习者行为之间仍有差距。
2. 需要更大规模的真实学生验证。
3. 多阶段 Agent 管线以更多推理成本换取可控性和个性化。
4. TutorBench 仍可扩展到更细课程、更长课程路径和更大学习者群体。
5. Book Engine 与 Partners 只是架构实例，其对保持、参与度、打扰成本和真实学习结果的影响需要纵向人类研究。

## 更广泛影响

个性化 Tutor 有机会扩大自适应教育支持的可及性，尤其是在高质量人类辅导稀缺时。但系统仍会继承 LLM 的幻觉、过度自信解释和细微推理错误风险。

因此，真实使用时应将生成内容视为辅助而非权威，保留来源验证，并鼓励学习者和教师用可信课程资料或人类教师核查重要结论。

# 附录 A：扩展相关工作译读

## A.1 工具增强的 LLM Agent

工具增强 Agent 使用外部检索、代码执行和规划突破模型静态参数的限制。相关研究从 ReAct 式推理行动循环发展到长周期调查、交互扩展和检索增强问题求解。DeepTutor 借鉴这些机制，但把它们分解为调查、逐步求解和写作，以便控制辅导中的证据与表达。

## A.2 LLM 个性化与记忆

已有记忆系统研究外部存储、层次化摘要、反思和长期用户模型。DeepTutor 的差异是把一次完整辅导交互保存为多粒度树，并让记忆 Agent 主动检索跨会话证据后再更新画像。

## A.3 知识追踪与智能辅导系统

传统 ITS 使用显式生产规则逐步诊断学习行为，代价是大量领域工程。BKT、DKT 和注意力知识追踪用潜在状态估计学生掌握度。LLM Tutor 扩大了领域覆盖和自然语言能力，但往往减少了经典 ITS 中可检查的学习者模型。

DeepTutor 没有直接采用 BKT/DKT 概率更新，而是维护可检索交互轨迹和文本画像。

## A.4 LLM 教育 Agent

相关工作已探索学生建模、多 Agent 课程规划、教育对话、知识追踪增强推荐、模拟学生训练与 RL 教学对齐。作者认为，这些系统常把问题辅导和练习题生成视为不同组件，学习者表示和表现信号共享有限，这与本文 §2.4 的双向任务耦合形成对比。

# 附录 B：系统实现算法

## B.1 Algorithm 1：闭环个性化辅导

输入为初始画像 `D^(0)` 和空轨迹森林 `F^(0)`。

```text
对每个会话 j：
  C_mem <- 根据旧画像、旧轨迹森林和当前任务组装个人上下文

  如果任务是 Solve(q)：
    C_rag <- 检索 q 的课程依据
    E_plan <- 结合 q、C_rag、C_mem 和历史轨迹进行调查
    P <- 生成子目标计划 <s_1, ..., s_K>

    对每个子目标 s_k：
      当 s_k 尚未解决时：
        ToolAgent 根据问题、计划、scratchpad、知识和个人上下文行动
        把本轮结果加入 scratchpad
        如果动作是 Replan，则根据已完成工作修改计划
      压缩已完成步骤

    a <- 根据 scratchpad 和 C_mem 迭代写出回答
    T_j <- 根据问题与答案构造轨迹树

  否则任务是 Generate(tau)：
    C_rag <- 检索主题 tau 的课程依据
    反复运行 IdeaAgent 与 EvaluateIdeas，直到获得题目模板 T_1...T_N

    对每个模板 T_i：
      生成题目、答案和解释
      Validator 独立验证
      若失败，按诊断反馈修订模板并重新生成

    T_j <- 根据主题和全部通过验证的题目构造轨迹树

  F^(j) <- 把 T_j 加入旧轨迹森林
  D^(j) <- 根据旧画像和 T_j 更新记忆
```

## B.2 Algorithm 2：TutorBot 自主 Agent 循环

算法描述论文写作时的 TutorBot/Partners 多渠道运行时。

```text
持续等待消息总线中的新消息：
  读取或创建该会话
  根据 Soul、长期记忆、skills 和近期历史构造系统上下文

  在最大轮数以内运行 ReAct 工具循环：
    调用 LLM
    若没有工具调用，得到最终回答并退出循环
    否则执行所有工具，把结果追加回消息上下文

  持久化本轮消息
  若会话接近上下文上限：
    把较早消息压缩进长期记忆并移动游标

  保存会话并把回答发回原渠道
```

> 译注：当前产品主分支已将旧 TutorBot 迁移为 Partners，并复用统一 Chat loop；该算法应按论文版本理解。

# 附录 C：TutorBench 构造细节

## C.1 来源资料

30 个知识库来自 OpenStax 教材章节和研究论文。教材包括 Calculus、Economics、Information Systems、Computer Science、Philosophy、Business 和 Writing 等；前沿研究材料包括 Agent Memory、DeepSeek-R1、LiveCodeBench、OpenVLA、Long CoT Survey 和 YOLOv9。

教材按连续章节拆为多个 PDF；研究论文各自构成一个知识库。

## C.2 任务生成与拒绝采样

任务类型权重为：

- 概念理解 `30%`
- 问题求解 `30%`
- 应用 `20%`
- 比较 `20%`

RejectSample 检查三项：

1. 缺口之间是否逻辑连贯。
2. 任务、初始消息与成功条件是否自然对应缺口。
3. 任务是否像真实学习者请求，内部是否一致。

判定采取“有疑问就拒绝”的严格策略。每个画像至少保留三个任务。每个任务记录类型、标题、描述、初始学生消息、目标缺口、预期暴露轨迹、成功标准和难度。

## C.3 benchmark 与 Trace Forest

benchmark entry 本身不保存 Trace Forest。Trace Forest 是运行期记忆：在多会话模拟中，启用跨会话记忆的 DeepTutor 后端才会创建和查询它。消融版本关闭该记忆，但所有系统使用相同 benchmark 条目，因此差异来自运行期是否读写记忆，而不是输入数据不同。

# 附录 D：评测协议与超参数

## D.1 学生模拟器

学生模拟器根据画像、缺口和任务初始化。知识缺口预先改写成第一人称信念，使 Agent 以学生身份相信错误观点，而不是从旁观者角度报告错误。

其行为规则要求：

- 不展示画像中标记为完全未知的知识。
- 学到新内容后尝试用自己的话复述，允许不完美。
- 只有解释真正解决困惑时才表示理解。
- 通常保持 1-4 句话。
- 可以继续追问、请求例子或练习。
- 只有没有任何剩余问题和请求时才能结束任务。

这种动态缺口节奏允许学生捍卫误解、部分接受纠正，并在得到足够支架后才结束，避免模拟器无条件赞同 Tutor。

## D.2 交互协议

评测分三步：

1. 离线生成 benchmark entry。
2. 多会话模拟：默认每个 session 最多 30 个学生回合，会话结束生成 5 道练习题。
3. LLM-as-Judge：评价 transcript 的五项教学指标、回合数和五项练习指标。

每份 transcript 评分三次并取平均。附录说明当前管线独立报告指标，不使用加权总分；主文 Table 2 的 OQ 是十项指标平均。

## D.4 人类偏好研究

45 个会话由 10 名具有相关训练的学生标注，包括 6 名本科生和 4 名研究生。每个领域由两人负责，系统身份隐藏，A/B 顺序随机。

每位标注者针对十个指标选择 A 更好、B 更好或无法区分。两名标注者意见不一致时，保守地计为平局。相关性统计基于十个“指标级 DeepTutor 胜率”数据点，而不是全部会话级标签。

## D.5 通用求解协议

正确性判断分两阶段：第一个 LLM 从自由文本中抽取最终答案，第二个 LLM 根据 benchmark 规则与 ground truth 比较。两步均使用 Claude Sonnet 4.6、温度 0。

通用求解实验禁用 SKG 和 DPM，不使用课程知识库、学习者画像或 Trace Forest。工具配置如下：

| Benchmark | 工具 | 最大 token | 并发 |
|---|---|---:|---:|
| HLE | code_execute, reason | 16384 | 30 |
| GPQA-D | code_execute, reason | 16384 | 50 |
| LiveBench | code_execute, reason | 16384 | 10 |
| GAIA | code_execute, reason, web_search | 16384 | 20 |
| AA-LCR | code_execute, reason | 16384 | 25 |

## D.6 Agent 超参数

| 模块 | Agent | Temperature | 最大 token |
|---|---|---:|---:|
| Solve | planner, solver, writer | 0.3 | 8192 |
| Question | idea, evaluator, generator, validator | 0.7 | 4096 |
| Personalization | summary, weakness, reflection | 0.5 | 8192 |

低温 Solve 强调稳定推理；较高温 Question 促进想法多样；Personalization 在一致性和画像适应之间取中间值。

## D.7 关键实现参数

- 薄弱点从 active 变为 resolved，不依赖数值置信阈值，而依赖 prompt 规则：近期正确作答并停止重复询问。
- 轨迹语义检索固定 `top_k=3`；TraceToolkit 的默认 `top_k=5`。
- Idea/Evaluator 检索 Level 1 会话根节点；Generator 检索 Level 3 错题模式。
- 单次轨迹详情截断到 6000 字符。
- Solver scratchpad 预算 6000 token；Writer 为 12000 token。
- 模拟器对话历史截断到 10000 字符。
- 知识图构造交给 LightRAG，PDF 解析由 RAGAnything 和 MinerU 完成。
- 使用 LightRAG 默认实体抽取，没有额外实体对齐和质量过滤。
- 每个 PlanStep 最多 5 次 ReAct；最多 10 个计划步骤、2 次重规划。
- Planner 预检索 3 个查询，RAG `top_k=8`。
- 题目想法循环最多 3 轮，每轮 5 个想法；Generator 最多重试 2 次。
- 记忆 Agent 最多运行 6 个 ReAct round。

# 译稿后的最小结论

按照论文原文，DeepTutor 的核心贡献不是 BKT、自动课程规划或模型参数自我训练，而是：

1. 用 Trace Forest 保存可跨会话检索的细粒度辅导证据。
2. 用三个记忆 Agent 把证据提炼为会话历史、薄弱点和教学反思。
3. 让问题辅导与练习题生成共享这些状态并互相反馈。
4. 用第一人称学生模拟器评价多轮个性化过程。

论文展示了 Mastery Path、Book Engine 和 Partners 等扩展，但其真实长期学习效果没有在本文中完成定量验证。阅读和汇报时，应把“论文验证的核心闭环”与“产品实现的扩展能力”分开。
