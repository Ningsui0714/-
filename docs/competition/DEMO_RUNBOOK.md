# Seeded Demo 演示脚本

## 0. 场前准备

1. 在干净终端执行 `bash start.sh demo`。
2. 确认浏览器进入启动脚本打印的 `/demo` 地址，并自动跳到全局“复习与错题”页面。
3. 确认后端 `GET /api/demo/status` 返回 `enabled: true`。
4. 确认 `GET /api/architecture/validate` 返回 `valid: true`。
5. 如演示桌面内部包，另建一个无敏感信息的临时项目目录；浏览器 seeded demo 不要求本地目录权限。

桌面附加演示可依次展示：选择父目录并创建项目文件夹、Explorer 中“关卡资料/项目文件”分组、Monaco 修改与 `⌘S/Ctrl+S`、hash 冲突提示、文件重命名和回收站恢复。强调这些操作不会产生掌握证据。

桌面学习文件演示：从“关卡资料”双击 `.lflecture/.lfexercise` 进入专用播放器；修改讲义后展示新版本和冲突保护，在练习中保存草稿、运行再正式提交，强调只有正式提交进入证据链。普通 `.py` 只作为文本查看/编辑，没有解释器、终端或运行按钮；Markdown 可切换预览/源码/分屏并显示相对图片。

桌面本地 Agent 演示：在关卡 Tutor 配置 `Seeded Demo Agent`，请求“让本地 Agent 修改项目文件”。第一张卡明确显示 Agent、任务范围、沙箱、联网边界和排除目录；首次确认后离线输出固定事件、测试与 diff。展示删除/移动逐项勾选和基础 hash 失效保护，再进行第二次确认写回。全程强调本地 Agent 是工具、不能改学习对象或五核，代码测试成功也不是掌握证据。

## 0.5 多项目学习工作台（约 30 秒）

1. 指出左侧项目树同时展示项目会话、正式路线、讲义/练习入口和五核记忆，但它只是服务端状态的导航投影。
2. 从关卡打开讲义或练习，展示顶部可关闭标签；点击标签上的并排按钮，展示最多三个学习编辑组。
3. 在主 Agent、项目、同一关讲义和练习标签间切换：全局与项目各自恢复对应 Tutor；同一关讲义和练习始终恢复同一个“关卡 Tutor”。学习设计与实践验证只作为关卡 Tutor 的内部能力，不切换成独立聊天人格。收起后保留窄入口，再一键完整展开。
4. 在同一关讲义与练习各发送一条消息，确认它们出现在同一个持久化关卡 Tutor 历史；切到另一关，确认消息和专属资源不出现。项目树、标签和分屏只改变 IDE 操作方式，不改变会话作用域。
5. 刷新页面，确认 learner 范围的标签和并排布局恢复。

## 1. 全局复习台（约 60 秒）

1. 指出总览中的今日到期、未完成纠错和错题数；切换“今日复习”“错题本”“即将复习”等标签。
2. 打开预置概念题，说明它来自三天前独立成功，现在优先展示后端校验过、尚未展示的变式；页面响应不包含正确项。
3. 打开详情抽屉，展示 Attempt、辅助等级、纠错案例、证据编号、间隔阶梯和调度原因。
4. 打开预置代码错题，说明未闭环 `RemediationCase` 的优先级高于普通到期题，可跳回原关卡继续重做。

## 2. 概念题闭环（约 90 秒）

1. 故意选择错误答案并提交。
2. 指出面板展示具体错误证据、误解标签和确定性策略 reason code。
3. 依次点击“换种讲法”“看步骤”或“看示例”。说明切换前的讲法会记录为对当前用户无效，而不是仅改变前端文字。
4. 点击“重做原题”，选择 `if not values:` 后提交。
5. 完成自动出现的新情境概念变式。
6. 指出“证据已回写”状态和 evidence IDs。

## 3. 代码题闭环（约 120 秒）

1. 保留 starter code 提交，展示空列表用例的除零失败。
2. 展示执行追踪、失败输入、预期与实际结果；需要时切换步骤或示例。
3. 在除法前加入：

```python
if not values:
    return 0.0
```

4. 点击“重做原题”，确认全部测试通过。
5. 在自动出现的变式中，预测新输入修复后的输出并提交。
6. 展示纠错完成和证据回写。

## 4. 架构说明（约 45 秒）

- LLM 可以渲染讲解，但 `RemediationStrategy` 按错误类型、历史无效讲法和阶段确定下一步。
- 三类主 Agent 都不能直接写五核；唯一写入链是 EvidenceEvent 到确定性 reducer。
- 星辰/Mock 工作流是可替换内容 adapter。离线 demo 不依赖它们，也不依赖外部网络。
- 注册表 API 把 Agent、kernel、capability、tool、skill、workbench 和重要事件放在同一可校验快照中。
- `ReviewSchedule` 只是由 Attempt/纠错事件重建的调度投影；复习成绩仍通过 `review_attempt_evaluated -> reducer` 更新 Knowledge/Practice。
- 桌面普通文件保存是零 kernel target 的操作事件；练习草稿/运行都不是证据，只有正式判题能成为掌握证据。

## 5. 现场故障切换

- LLM 或网络不可用：继续使用 demo；所有闭环逻辑是本地确定性的。
- 日常数据库状态异常：停止服务后重新运行 `bash start.sh demo`，演示库与日常库隔离且 seed 幂等。
- 浏览器未跳转：手动打开启动脚本打印的前端地址并追加 `/demo`。
- 端口占用：先执行 `bash start.sh stop`，确认旧进程结束后重启。
- 需要证明版本：打开 `/api/architecture/registry`，记录 version、digest 和 validation_errors。
- 桌面目录不可用：切回浏览器 `/demo`；桌面文件能力与 seeded 学习闭环相互隔离。
