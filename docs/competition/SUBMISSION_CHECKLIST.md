# 比赛提交清单

此清单按参考比赛方案的材料编号维护；最终提交前以官方最新通知复核。

## 01 参赛信息

- [ ] 系统报名信息与报名表一致。
- [ ] 负责人、成员、学校、联系方式完成复核。
- [ ] 所需签字、盖章和扫描件已完成。

## 02 作品 Demo

- [ ] `bash start.sh demo` 在一台未配置 LLM key 的机器上可运行。
- [ ] Demo 地址、星辰 Agent/Workflow 编号（如使用）和操作说明完整。
- [ ] 录屏覆盖答错、纠错、讲法切换、重做、变式和证据回写。
- [ ] 录屏展示项目树、多标签/并排编辑组，以及可完整展开、缩回并随操作自动切换的 Agent 对话窗口；确认三类对话仍使用各自原接口，不合并会话、handoff 与五核边界。
- [ ] 记录 architecture registry version/digest。

## 03 作品方案

- [ ] 明确“谁 + 哪个教学/实训环节 + 什么痛点”。
- [ ] 描述三类主 Agent、五核、Evidence Ledger 和可选星辰 adapter。
- [ ] 说明确定性策略与生成式讲解的边界。
- [ ] 展示运行效果、创新点、可扩展方式、迭代计划和团队分工。
- [ ] PPT 文件大小符合要求。

## 04 作品代码与技术报告

- [ ] 代码可复现，环境和启动命令明确。
- [ ] seeded demo 不包含真实学生数据、密钥或私有 URL。
- [ ] 后端纠错/架构测试通过，前端 production build 通过。
- [ ] 领域知识条目、来源编号/页码和授权状态可追溯；若规则要求至少 50 条，已完成计数。
- [ ] 外部工作流版本和 adapter 输入/输出契约已固定。

## 05 伦理与安全合规性声明

- [ ] 不使用未经脱敏的真实个人敏感数据。
- [ ] 不生成或提交伪造学术数据、虚假文献。
- [ ] 产品中存在明显的 AI 生成内容标识。
- [ ] 对代码执行、外部来源和模型输出的风险与限制有说明。
- [ ] 团队负责人签字或按要求盖章。

## 06 其他材料

- [ ] 2–3 名目标学生或教师的具体试用反馈。
- [ ] 测试脚本、测试结果、截图/录屏、数据字典和知识来源表。
- [ ] 已知限制、失败降级和现场 runbook。
- [ ] 知识产权和第三方素材许可检查完成。

## 最终复核

- [ ] 压缩包和内部目录按官方格式命名。
- [ ] 在离线或受限网络环境完整走一遍 demo。
- [ ] 不提交 `.env`、API key、Cookie、真实账号数据或日常 SQLite 数据库。
- [ ] 重新核对截止日期、邮箱/平台入口和最新补充通知。
